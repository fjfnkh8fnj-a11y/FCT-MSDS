# FCT 교육관리 × Neon 준비 — rev.1

> 진행상태: PostgreSQL 스키마 준비 완료 / Neon 프로젝트에 적용되지 않음 / 홈페이지 변경 없음.
>
> 기존 교육관리 홈페이지는 여전히 브라우저별 localStorage 시연용입니다. 실사용 직원 개인정보를 입력하지 마세요.

## 구축 목표

- 직원 100명 이상 동시 로그인, 수강, 평가, 서명 제출 시 기록 누락 및 혼입 0건을 부하 시험으로 확인
- 직원은 본인 배정 교육만, 관리자는 부서 및 전체 교육이력 열람
- 정기교육·상시 채용교육, 교육월 및 수료일, 교육일지와 서명부 출력 지원
- GitHub Pages(현재 화면) + Neon Managed Auth + Neon Functions + Postgres + 비공개 Object Storage

## 초기 Neon 구성 절차

1. FCT-EDU-TEST 테스트 프로젝트를 Neon 계정에 준비한다. 개인정보 국외 저장 여부와 사용 리전을 회사 승인사항에 맞춰 확인한다.
2. Neon Auth와 Data API를 활성화한다. 직원이 인증 없이 DB에 접근하지 못하도록 한다.
3. 서명/교육 첨부파일용 Object Storage를 private로 구성한다. 파일은 권한·짧은 유효기간을 검증하여 제공한다.
4. 인증과 Data API의 authenticated 역할이 준비된 뒤 테스트 브랜치에서 001_schema_rev.1.sql을 적용한다.
5. Data API의 GRANT/REVOKE 및 RLS 역할 매핑을 확인하고 직원/관리자 접근 테스트를 진행한다.
6. 실제 관리자 계정으로 로그인하여 확인된 UID를 관리자 역할에 매핑한다. 공개 소스에 관리자 비밀번호를 넣지 않는다.
7. 데이터 변경 전 서버 함수에서 직원 본인 확인, 과정 배정, 영상 유효시간·중복 시청 검증, 평가 채점 및 시도 제한, 서명 업로드, 수료 판정 처리.
8. 현재 브라우저 저장 기반 교육 화면을 호출 단위가 작은 서버 API로 바꾸고 시험한 뒤 배포한다.

## 현재 시연판 전환 주의

- 기존 교육관리 코드에는 load()/save()가 localStorage를 사용함.
- 사용자 전체 기록을 한 JSON으로 덮어쓰는 방식을 클라우드에 그대로 옮기면 100명 동시 제출 시 덮어쓰기가 발생할 수 있음.
- 직원/과정/배정/영상별 진도/평가시도/서명을 별도 행과 API로 분리하여 저장.
- 진도·평가점수·이수결과·서명 확정은 직원 브라우저의 단순 숫자 제출만 신뢰하지 않고 서버에서 검증.
- 정답은 퀴즈 문항과 분리해 공개 API로 노출하지 않음.
- 과거 시연 데이터는 자동으로 실제 교육기록에 섞지 않음.

## 100명 동시 접속 필수 시험

- 서로 다른 직원 100개 계정으로 로그인, 과정 조회, 영상 진도, 평가, 서명을 동시에 제출.
- 제출 요청 건수와 DB 기록 건수를 대조하여 누락 0건, 다른 직원 기록 혼입 0건 확인.
- 중복 제출 / 통신 끊김 / 새로고침 / 재시작 / 재연결 / iPhone Safari / Android Chrome 재시험.
- 회사 와이파이에서 100대 동시 YouTube 재생은 무선 AP와 회선 대역폭 별도 현장 검증.
- Neon 무료 요금제 한도 내 성능을 사전 보장하지 않음. 측정 후 운영 판단.

## 자동 백업 설계

- 하루 1회 DB 전체 백업. 직원 서명·첨부파일 스토리지는 DB와 별도로 백업.
- 날짜별 신규 백업 생성. 최근 30일 일별 및 월말/연말 보존 기준은 회사와 협의.
- 외부 백업 사본 암호화, 관리자 접근통제, 정기 복원시험.
- 월간 교육일지·이력·평가·서명은 HTML/PDF 읽기 전용 열람용 백업 제공.

## 보안

- Neon DB 접속문자열/비밀번호/관리자 키를 GitHub 공개 저장소 및 웹 브라우저에 절대로 기록하지 않는다.
